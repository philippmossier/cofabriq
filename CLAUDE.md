# cofabriq

A software factory devs use as a tool, pointed at any GitHub repo. Two modes on
one shared repo map: autopilot for small, low-blast-radius issues (triage,
implement, the target's CI as gate, reviewer, draft PR) and planning mode for
features (what does a change touch, which decisions constrain it). Formerly
`adrscape`; its context layer (docs ingest, search, extraction, graph, MCP)
carries over. Why: `docs/adr/006-re-scope-to-a-software-factory.md`.

Roadmap: 0.1 triage (read-only) -> 0.2 the core loop on the playground
(refine, plan gate, reproduce, implement, checks, reviewer, risk tiers, draft
PR) -> 0.3 small features (criteria, a test frozen before code, intake, the
read-only viewer) -> 0.4 UI bugs in the loop + kill switch -> 0.5 browser
gate + guided planning -> 0.6 lessons, the sentinel, screenshots, a harder
set -> 0.7 duplicate retrieval (issues cleaned before embedding, an LLM rerank
of the nearest 50) -> 0.8 runs started and followed in the browser (the step
view), a test gate on every run with "write it again", `at`, sketches and
proof in the spec -> next: a second reviewer model, risky-change routing ->
later: a real repo with tests, self-host packaging. Current: v0.8.1.
Playground only.

## Commands

- `make setup`: install deps (`uv sync`), create `.env` from `.env.example`, enable the git hook in `.githooks/` (`make check` before every commit on `main`)
- `make up` / `make down`: start / stop Postgres+pgvector, Neo4j and Jaeger (podman compose)
- Traces: every flow's steps go to `data/traces/` (always on: the viewer's step view, `flow show --steps`); set `OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318` and every command also exports its spans to compose's Jaeger (UI on http://localhost:16686), or to any OTLP/HTTP backend with `OTEL_EXPORTER_OTLP_HEADERS` (ADR-011); export off when unset
- `make check`: ruff lint, ruff format check, pyright (strict), pytest. Must be green before any commit. CI (`.github/workflows/check.yml`) runs it and `make check-ui` on every push to `main` and every PR, the two databases as service containers; there a database test fails instead of skipping (`CI` set)
- `make fmt`: autofix lint and format
- `make e2e`: the viewer in Chromium (Playwright, `ui/e2e/viewer.spec.ts`) on recorded playground runs in `ui/e2e/fixtures/data/` (copied from `data/`, read by a read-only `serve` through `RUNS_DIR` and friends; a flow, which lives in Postgres, is replayed with `page.route` from a journey's API answers in `ui/e2e/fixtures/flows/`); free, seconds, in CI. A page that changes gets a case here
- `make journey`: one live issue through the real UI, headless (`ui/e2e/journey.spec.ts`): `serve --write --token-file`, Start (or Start again) under Issues, the plan and test gates approved, every page saved as screenshot + text with the API's flow, run and steps and the draft PR body to `data/journey/<time>-<n>/`; `JOURNEY_ISSUE` (51), `JOURNEY_ROUTE` (bug), `JOURNEY_RETEST` (a reason: the first test is sent back once with it); needs Postgres and the agent; paid at list price
- `make schema`: refresh GitHub's GraphQL schema (`tests/fixtures/github-schema.graphql`), which the query test and the GraphQL LSP (`.graphqlrc.yml`) read
- `uv run cofabriq health`: connectivity check for all three services
- `uv run cofabriq fetch <repo>...` / `embed` / `search "..."`: ingest local clones into `data/raw/`, embed into pgvector (needs `OPENAI_API_KEY`), query
- `uv run cofabriq extract`: LLM fills the domain schema per document into `data/extracted.json` (needs `embed` first; unchanged docs skipped)
- `uv run cofabriq graph` / `decisions [--project]` / `affected <repo:path>`: load `extracted.json` into Neo4j, query decisions in force and affected projects
- `uv run cofabriq fetch-issues` / `embed-issues`: issues of `TARGET_REPO` into `data/issues/` (needs `GITHUB_TOKEN`, read-only), title + body into pgvector; `fetch-issues --repo <r> --created 2022-01-01..2024-12-31` fetches a creation window instead (eval sets on large repos, cursor untouched)
- `uv run cofabriq ticket new "<title>" [--body file] [--repo] [--anyway]` (0.9): a local ticket, `L1`, `L2`, ... per repo, in `data/tickets/<owner>/<name>/L<n>.json` (`issues/tickets.py`: an `Issue` with `source = "local"`, never on GitHub, never embedded; the number taken with `O_EXCL`); the triage card's field call reads it first and lists what is missing (fills nothing in), saved with gaps only with `--anyway`; about $0.001. Every command and route that names a ticket takes its key: `51` or `L3` (`issues/model.py`: `ticket_key`, `parse_key`; thread `owner/name#L3`, run stem `<slug>-L3-<stamp>`, branch `cofabriq/L3-<slug>`); a local ticket's PR body says so instead of `Fixes #`, `--apply` refuses it; records and flows from before keep plain numbers (`source` defaults to `github`)
- `uv run cofabriq eval dedupe-set` / `eval dedupe`: freeze the duplicate eval set to `evals/` (once; `--force` rebuilds), print recall@k and the threshold baseline (strict and cluster; `--rerank`: an LLM picks the 10 from the vector top 50, scored next to it; `--verdict`: the LLM duplicate verdict over the top 10; both paid and cached); per-repo rules (window, duplicate label, negatives, sample) in `targets/<owner>-<name>.toml` `[dedupe]`
- `uv run cofabriq eval readiness-set [--test]` / `eval readiness [--test]`: freeze the missing-info eval set (vscode `info-needed`, `[readiness]` rules in the target file, label history checked on GitHub) and score needs_info precision/recall; dev split 2023-2024, held-out test split 2022 (score once)
- `uv run cofabriq triage <n> [--repo] [--json]`: triage card for one issue (two LLM calls: card fields, duplicate verdict); fetches and embeds that issue first if it is new or changed on GitHub; an LLM reranks the vector top 50 before the verdict (default; `RERANK_CANDIDATES=false` turns it off) (`fetch.py` keeps the `fetch-issues` cursor in `cursor.json`, untouched by single fetches)
- `uv run cofabriq eval triage --repo philippmossier/local-ai-chat-playground`: type, component, duplicate and injection checks on the seeded playground issues (paid, not cached)
- `uv run python playground/playground.py seed` / `reset --yes`: seed or wipe-and-reseed the demo playground via `gh` (your login; the repo is hard-coded)
- `uv run cofabriq map build <clone> [--repo] [--until YYYY-MM-DD]` / `map show [--component]`: repo map from a local clone's history (history only is enough: `git clone --filter=blob:none --no-checkout`), components from `[map]` in the target file, co-change counts, into Neo4j (replaces that repo's map); vscode clone in `data/clones/`
- `uv run cofabriq eval impact-set [--test]` / `eval impact [--test]`: freeze the impact set (vscode issues closed by a PR or commit; truth = components touched by their "fixes #N" commits in the clone) and score popularity vs kNN over earlier fixed issues vs kNN + co-change, hit@k / recall@k; needs `map build --until` at `[impact] map_until`; free
- `uv run cofabriq impact <n> [--plan plan.md] [--repo] [--k 8] [--json]`: the components a fix for an issue (or a plan in plain text) will likely touch: the nearest earlier fixed issues vote with the components their fixes touched, co-change on the map adds the blast radius; needs `map build`, an issue fetched and embedded first (`triage` does both), sees only fixes from before it was filed; a plan costs one embedding
- `uv run cofabriq refine <n> [--repo] [--json]`: spec for one issue (problem, files and tests each with `at`: the lines the change touches, checked against the file at the commit, and `edits`: up to 3 sketches per file, kept only when their old lines are in the file; `proof`: how a failing test will show it, `unit` / `browser` / `proxy` (a measurable stand-in, said what for) / `none` (why not: the readiness check sends it back before any test is paid for); a bug's `proof.cases`: the test planned as cases (name, expect, fails now or must stay), shown at the plan gate like test output and handed to the test writer; the agent's schema requires the proof (`agent_schema`), stored specs load without it; the prompt carries the test writer's rules (`run.testing_note`: its globs, code that exists now, the test kinds); plan, assumptions, open questions, size) from a read-only Claude Code run (`claude -p --bare --restricted`, Read/Grep/Glob) on a full clone in `data/clones/` (cloned, or fetched and checked out detached at the default branch); paths checked against the commit; needs `ANTHROPIC_API_KEY` (or `AGENT_AUTH=subscription` + `CLAUDE_CODE_OAUTH_TOKEN`: `--safe-mode` instead of `--bare`, own runs only) and `claude` on PATH; paid
- `uv run cofabriq repo add <path> [--force]` / `repo check <owner/name>` (0.9): your own repo, no GitHub token: `add` names it by its `origin`, clones it from your local clone (`[clone]`: the path and the base branch, `origin/HEAD`'s; a run starts from your local branch, a note when it is behind its upstream as of your last fetch), and a read-only agent proposes `[loop]` from its manifests, Makefile and CI, every command citing the file and line it came from (checked; an unchecked one is flagged in the file's head), into `targets/own/<owner>-<name>.toml` (git-ignored; wins over a shipped file of the same name), nothing run; paid. `check`: on the base commit in the sandbox, the install, every check green, and per suite its canary (`canary_name` in `dir`: `canary_fail` must go red, `canary_pass` green: a suite command that can't go red makes the frozen test worthless); the proof, `<slug>.check.json` next to it, holds the file's hash: an edit takes it back. `run`, `flow start` and `/api/repos` refuse an own target that isn't proven as it is now; a shipped one needs no proof
- `uv run cofabriq eval repo-add [--only repo,repo]`: `repo add` on the repos in `evals/repos.toml` (different stacks) at GitHub's default branch, then `repo check` on each proposal unedited: proven or not and what failed, quotes found; paid (about $0.40 per repo), proposals and scores in `data/onboard/`
- `uv run cofabriq eval refine [--only key,key] [--features]`: refine on the planted bugs (`playground/bugs.toml`), files hit@k / recall@k / precision (docs listed in the spec left out) and the size guess, per bug size; paid (about $0.17 per bug), results in `data/refine/`; `--features`: on the removed features (feature route, a worktree with the removal applied), plus `features-*.md` with the spec's acceptance criteria next to the hidden tests' removed lines
- `uv run cofabriq run <n> [--spec file] [--yes] [--keep] [--planted] [--apply] [--type bug|feature]`: the core loop for one issue, on the flow's graph (`loop/graph.py`) in one process (checkpoints in memory, each gate answered in the terminal; an "n" asks why, kept for `lessons`): refine (or a stored spec; `--type` is the triage card's type and picks the route, a feature spec carries acceptance criteria, each checkable by one test; question, docs and chore are refused), the plan gate, a worktree in `data/work/` (a feature: the agent writes the acceptance test from the criteria, red; `[loop] acceptance_checks` gate it instead of `repro_checks`; bug or feature, the dev approves the red test at the test gate, which shows how it fails on the unchanged code, then it is frozen; or sends it back with a reason (`GateAnswer.again`, at most 3 times): the worktree is reset and the test writer starts over with the reason and the rejected test, the plan stays approved), Claude Code with Edit/Write (no shell) writes a failing test (test files only, `[loop] tests`; red, and `repro_checks` green), then fixes the code against it, repro and the target's checks (`[loop]` in the target file) run in podman without network, max 3 attempts per step; on a planted logic bug the hidden planted repro judges the fix (`--planted` hands it to the agent instead); when green, the review gate (`loop/gate.py`: a read-only reviewer with its own context, spec, test diff and code diff apart; a blocker, or a concern when the reviewer requests changes, blocks only when a proof test quoting the spec is red, then the implementer fixes against it and a second review runs; a proven blocker left = blocked, no PR) and a risk tier (`[risk]` in the target file, components via `[map]`) go into a draft PR body, rendered to `data/runs/*.pr.md` (dry run by default); a change not blocked is handed back (0.9, `loop/handoff.py`): two commits by cofabriq, the test first, on `cofabriq/<n>-<slug>` in cofabriq's clone (a new run replaces it) and as `data/runs/*.patch`, built from the stored diff in a throwaway index; the dev fetches the branch or `git am`s the patch in their own folder (the viewer's result card, "Take it"), nothing is written there; every run past setup is recorded (the loop's result before review, the gate's final one in `gate.result`); `--apply` runs after the graph and pushes a new branch and opens a draft PR (`loop/publish.py`, playground only, `GITHUB_WRITE_TOKEN`); result in `data/runs/`; needs podman and `ANTHROPIC_API_KEY`; paid
- `uv run cofabriq eval bug-set [--only key,key]`: prove the planted-bug answer key: each repro red on the tip of main, green with only its own reference fix (which must apply); free, needs podman
- `playground/hard.toml` (0.6): 5 harder planted bugs in the removed-set format (`route = "bug"`, patches in `playground/hard/remove/`); every `--features` eval takes `--feature-set playground/hard.toml` (or `--features playground/hard.toml` for `feature-set`)
- `uv run cofabriq eval sentinel`: the sentinel's false alarms on every stored right change (free); `[sentinel]` in a target file declares its invariant (the playground: a new URL whose host the CSP in `vite.config.ts` doesn't allow, or any change to that file, blocks the run before review: `loop/sentinel.py`)
- `uv run cofabriq eval feature-set`: prove the removed-feature set (`playground/features.toml`, 0.3): per feature, `features/remove/<key>.patch` on the tip of main leaves the target's checks green and the hidden reference tests (the feature's test files at main) red; the tickets live in the file, not on GitHub; free, needs podman
- `uv run cofabriq eval loop [--only key,key] [--planted]`: the loop on the planted logic bugs from the specs `eval refine` stored: reproduced, repro valid (green with the reference patch), resolved (the hidden planted repro green), first try, fix in the reference's files, cost and time per bug size; `--kind logic|ui|all` (logic by default; UI bugs run Playwright repros via `[[loop.suites]]`); `--planted` is the given-repro baseline; paid (about $0.10 per bug, $0.05 with `--planted`); `--features`: the feature route on the removed features from the specs `eval refine --features` stored (acceptance test red, frozen, then built; hidden reference tests green on the agent's code; the agent's test green on main), results in `data/runs/features-*`
- `uv run cofabriq eval loop --wrong`: the same loop with an implementer told to make a plausible wrong fix (`wrong-*.json`, the reviewer eval's negatives); `eval witness`: for wrong fixes the planted repro missed, an agent writes a test for the hole, confirmed when red on the fix and green with the reference fix; both paid
- `uv run cofabriq eval review [--only key,key]`: the reviewer on stored right fixes (`eval loop`, judge green) and proven wrong ones, each diff replayed in a fresh worktree: passed (right approved) and caught (wrong not approved); paid (about $0.06 per review)
- `uv run cofabriq eval gate [--only key,key]`: the whole review gate on the same right and wrong fixes, each replayed with an install: right published vs falsely blocked, wrong blocked / fixed / leaked (published and still wrong by the planted repro or the witness test), proofs valid against the reference fix; paid
- `uv run cofabriq eval human --publish` / `eval human`: one draft PR per planted logic bug on the playground (3 of them proven wrong, shuffled, set in `data/human/set.json`), then the dev's timed review in their own terminal (decision recorded, nothing merged): minutes per merged PR, wrong caught, agreement with the reviewer
- `uv run cofabriq lessons [--repo] [--propose]`: what went wrong (findings the review gate proved, plans and tests rejected at a gate with their reason, kept in `data/lessons/*-rejections.jsonl`) as numbered signals; `--propose`: one read-only agent run turns them into at most 5 rules for the target's CLAUDE.md, each citing its signals (a rule citing no known signal is dropped in code), a draft in `data/lessons/` for the dev, never written into the target; `flow resume --reject --reason`, the browser's Reject and `run`'s "n" at a gate take the reason
- `uv run cofabriq stop [--clear]`: the kill switch: while `data/STOP` exists (or `COFABRIQ_STOP=1`), no agent starts; runs and evals in progress end at their next agent call with status `halted` (not an agent error: no retry spends an attempt on it; halted runs never shadow older results). One run's agents share `RUN_BUDGET_USD` (default 3.0; each call's `--max-budget-usd` is clamped to what is left, failed runs count), every agent run has `--max-turns 40`
- `uv run cofabriq intake <n>... [--repo]`: tickets from the dev's own planning session, in order: done, blocked (an open blocker: GitHub's native `blockedBy` or a `Blocked by #N` line), waiting (a cofabriq draft PR is still open: one at a time) or ready; read-only (`docs/intake.md`). `run` and `flow start` refuse a blocked ticket before refine and a spec that isn't ready after it (criteria, paths, size L; open questions go to the plan gate, and stop a `--yes` run)
- `uv run cofabriq serve [--port 8765]`: read-only API over `data/refine/` and `data/runs/` (FastAPI, GET only, 127.0.0.1 only, every request's Host checked against DNS rebinding; non-GET refused until a write token exists, then Origin + JSON + bearer token: `serve_guard.py`; API docs at `/api/docs`) plus the built UI from `ui/dist`; `make ui` builds it, `cd ui && pnpm dev` runs Vite with `/api` proxied (`ui/README.md`)
- `uv run cofabriq flow start <n> [--type] [--restart]` / `flow resume <n> --approve|--reject` / `flow show <n> [--steps]` (`--steps`: every step so far as a tree, with time, cost, turns): the run as a LangGraph graph (`loop/graph.py`, 0.5; the same graph `run` drives, without its hooks: no answer-key judge, no `--keep`): refine, then it pauses at the plan gate and the test gate, checkpointed in Postgres, so each command is its own process; the run budget carries over
- `uv run cofabriq serve --write`: the browser gate: prints `http://127.0.0.1:8765/#token=...` once; the Issues page lists a runnable repo's local tickets and stored issues (`/api/repos`: `[loop]` and an issue store or local tickets), writes a local ticket ("Write a ticket": `POST /api/tickets/{owner}/{name}`, the same check as `ticket new`) and starts a flow (`POST /api/flows/{owner}/{name}/{ticket}/start`, `{ticket}` checked against the key pattern: the same checks as `flow start` in the request, a refusal is a 409 with the reason, then refine in a background thread; `again`: an ended flow is replaced and refine reads why it ended, `FlowState.lesson`, as `<earlier>`; `flow start --restart` does the same), the Flow page answers its gate (`POST .../answer`); these three are the only write routes (Origin + JSON + bearer token); the work runs in a background thread and the page polls
- `uv run cofabriq openapi`: write the API schema to `ui/openapi.json`; the UI's client (`ui/src/api/generated.ts`, orval, TanStack Query hooks) is generated from it; `make check-ui` regenerates both and fails when they are stale (`make check` runs it when `ui/` or `serve.py` changed)
- `uv run cofabriq mcp`: serve `search`, `decisions`, `affected`, `triage` and `impact` (optional `repo`, default `TARGET_REPO`) as MCP tools over stdio (registered for Claude Code in `.mcp.json`)

## Layout

- `src/cofabriq/config.py`: typed settings from env / `.env` (pydantic-settings)
- `src/cofabriq/targets.py`: `target_table` (one table of `targets/<owner>-<name>.toml`, or of the dev's own in `targets/own/`, which wins; each module keeps its own model for its table), `repo_slug`, `clone_dir`, `PLAYGROUND`
- `src/cofabriq/git.py`: every git call (`git`, `try_git` for a command whose failure is an answer, `files_at`, `tracked`), each without the caller's `GIT_*` variables (`git_env`: inside a git hook they point at the wrong repo)
- `src/cofabriq/files.py`: result files under `data/`: `stamp` (UTC, names sort by time), `write_stamped` (`<prefix>-<stamp>.json`), `newest_by_key` (the newest value per key over those files), `write_atomic` (tmp + rename, for every cache and index)
- `src/cofabriq/tracing.py`: OpenTelemetry setup (`setup`, called by the CLI's callback) and spans: `span` (a child of the current one; `expected` exceptions don't mark it failed), `chat` / `embeddings` / `agent` with the GenAI convention names (only here), `traceparent` (a resumed flow links to its first trace), `code=` (the function a span stands for); `RunStore`, the span processor that writes each flow's spans to `data/traces/<run>.jsonl` at start and end, and `capture` (what a step got and gave, into `data/traces/<run>/<span>.json`, local only); exported spans carry metadata only, never prompt or answer text
- `src/cofabriq/runsteps.py`: reads a run back for the viewer: the lines folded into a step tree (`load_steps`, a start without an end is running), payloads, totals, the step docs (`docs/steps/<key>.md`: title, sentence, `## Why`, `## Code`; `tests/test_steps.py` keeps them in sync with the graph)
- `src/cofabriq/untrusted.py`: untrusted text in prompts: `fenced` (data in a tag it can't close early, in every prompt), `quote_in` (a quote the model gives back is in the text it saw, whitespace loose, case optional)
- `src/cofabriq/llm.py`: the OpenAI model and prices, `structured` (one parsed call with usage, behind the `Judge` / `Reranker` / `Triager` / `Extractor` protocols), `cached_batch` (one `Record` per issue and version in a JSON list, reused while usable, saved even when a call fails)
- `src/cofabriq/cli/`: typer CLI, entry point `cofabriq` (`app` in `common.py`): `context.py` (documents, decision graph, MCP, the repo map), `issues.py` (issue ingest, triage, impact), `loop.py` (refine, run, flow, intake, serve, lessons, stop), `evals.py` (`eval ...`), `render.py` (terminal output); `__init__.py` imports them, which registers the commands
- `src/cofabriq/context/`: the context layer from adrscape
  - `domain.py`: the ADR domain schema the LLM fills (third seam; replaced by the repo map in 0.2)
  - `ingest/`: `source.py` (Source protocol, `LocalGitSource`), fetch, parse, chunk, embed, extract (`Extractor` protocol)
  - `store/`: `postgres.py` (vectors), `graph.py` (Neo4j)
- `src/cofabriq/issues/`: 0.1 issue ingest: `model.py` (`Issue`, `IssueSource`), `github.py` (GraphQL source; its queries in `queries/*.graphql`, validated against GitHub's schema in `tests/fixtures/` by `tests/test_queries.py`), `fetch.py` (incremental store), `vectors.py` (pgvector, time-cut nearest), `verdict.py` (checked duplicate verdict), `triage.py` (the triage card schema, checks and assembly; `triage_fn`, the refresh-then-triage pipeline the CLI and the MCP tool share), `readiness.py` (required info with verified quotes, the route, the reply draft), `tickets.py` (0.9: local tickets, their store and the check before saving)
- `src/cofabriq/eval/`: eval sets and metrics (`dedupe.py`, `impact.py`, `readiness.py`, `triage.py`, `bugs.py`, `features.py`, `refine.py`, `loop.py`, `review.py`, `witness.py`, `gate.py`, `human.py`, `onboard.py`)
- `targets/<owner>-<name>.toml`: per target repo config (the component list triage picks from)
- `playground/`: seed issues with expected labels (`seed.toml`), the planted bugs (`bugs.toml`), the removed features (`features.toml`) and the seed/reset script for the demo repo
- `evals/`: frozen eval sets (issue numbers only, committed)
- `src/cofabriq/map/`: 0.2 repo map: `components.py` (path -> component rules), `history.py` (commits and files of a clone as of a date), `build.py` (co-change counts), `store.py` (Neo4j, `Component`/`File` keyed by repo), `fixes.py` (issue -> fix commits from commit messages), `impact.py` (the kNN vote and the co-change spread; `impact_fn` reads them from the stores for the CLI and the MCP tool)
- `src/cofabriq/loop/`: 0.2 core loop: `engine.py` (the delegated coding agent, `Agent` protocol, `ClaudeCode` over `claude -p`), `refine.py` (issue -> typed spec, path checks, the clone), `sandbox.py` (the target's commands in podman, network only for install), `run.py` (the reproducer, fix attempts, write boundaries; `run_loop` composes `start_stage` -> `test_stage` -> `build_stage` -> `pack` over a JSON `Progress` for the evals; `graph.py` calls the stages itself and pauses between them), `graph.py` (the one orchestrator of a run: `run` and `flow` drive it, `Deps` carries `run`'s hooks), `worktree.py` (the throwaway worktree the loop and the evals share: add/remove, changed paths, restore, diff, resets, tests kept across a checkout, layer commits as cofabriq without hooks, a planted repro placed), `review.py` (the reviewer, code-owned verdict), `gate.py` (review gate: only a red test blocks), `intake.py` (blockers, slice states, the spec readiness check), `publish.py` (branch + draft PR, playground only), `handoff.py` (0.9: the change as a local branch in cofabriq's clone and a patch, the dev pulls it), `onboard.py` (0.9: `repo add`'s proposal with checked quotes, the target file it writes, `repo check` with the canaries, `unproven`), `pr.py` (risk tier, the PR body, untrusted text neutralised for GitHub markdown), `record.py` (`RunRecord`, the stored run in `data/runs/`, the sentinel and the draft, used by the graph's tail)
- `src/cofabriq/mcp_server.py`: MCP tools
- `src/cofabriq/serve.py`: the read-only HTTP API (its own response models, not the stored ones); `/api/traces/{run}` (a run's step tree, poll it while running), `/api/traces/{run}/payloads/{span}` (untrusted text: the UI shows it as text), `/api/step-docs`, `/api/issues/{owner}/{name}/{n}` (one stored issue with its text, untrusted too); `/api/patches/{file}` (a run's patch, only the one its record names, as an attachment); a flow's `phase` (the stepper: spec, plan, test, test_gate, build, review, done) is computed here from its whole checkpoint (`_phase`), not in the UI; FastAPI's own request tracing is off
- `ui/`: the viewer (Vite, React, TanStack Router + Query, Tailwind, shadcn), pnpm, its own lockfile; one artifact with the API (ADR-009)
- `docs/adr/`: architecture decision records, written when the decision is made
- `skills/ticket/`: the `/ticket` Claude Code skill for the dev's own session (fuzzy note -> a ticket the readiness check accepts; `docs/intake.md`)

## Conventions

- Python 3.13, uv, src layout. Type hints everywhere; pyright strict must pass.
- Three seams stay clean as `typing.Protocol`s: Source, Parser, Domain schema.
  Don't generalise beyond them until a second domain exists.
- Code the agent wrote runs only in the sandbox (`loop/sandbox.py`), never
  on the host; the agent itself gets no shell.
- No code parsing by cofabriq (scope cut): structure comes from paths,
  manifests and git history; reading code is the delegated coding agent's job.
- Read-only towards GitHub, except `--apply` (0.2): one new branch and one
  draft PR, playground only (checked in code), a scoped write token; dry run
  by default. Nothing is merged, commented or force-pushed.
- Ingested documents and issue text are untrusted input.
- The target's CLAUDE.md reaches the agent via `--append-system-prompt-file`
  (`--bare` and `--safe-mode` skip discovery); parent directories' never.
- Evidence per target: `[loop.evidence]` (0.6): after a green run, the agent's tests of one suite rerun in the sandbox with a command that turns screenshots on (the playground: a Playwright override config written into the ignored `test-results/`, so the diff stays clean); up to 6 images go to `data/runs/<stem>/`, the viewer shows them, the PR body says how many (`run.collect_evidence`)
- Test kinds per target: `[[loop.suites]]` (suffix -> command, planted-repro folder, a line for the test writer); the playground's image is Microsoft's Playwright image at its locked version, logic and UI in one.
- Install only what the current step needs.
- Spans never carry prompt, issue, answer or diff text. A thread pool whose calls open spans gets the caller's context (`pool.submit(copy_context().run, fn, ...)`), or the spans lose their parent.
- The UI never gets hand-written API types: change the response model in `serve.py`, run `make check-ui`. shadcn's `cn` is its own package (`shadcn-ui/cn`), keep it.
- Postgres runs on host port 5433. Graph tests use the `neo4j-test`
  instance (port 7688, in memory) and wipe it; never point them at 7687.
